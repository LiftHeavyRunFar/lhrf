# Running preparation v2

`src/running-preparation.js` supplies pure, offline assessments to the shared engine only for new version-2 proposals. Existing saved policies keep their original prescriptions. Its native output is subsequently fitted to actual visits and audited against the final calendar; a pre-scheduling budget is not credited as completed or scheduled mileage.

- Race work uses current performance equivalents. A faster aspiration is disclosed and never used to accelerate prescribed work paces.
- 5K/10K preparation rotates threshold, race-pace and controlled ladder/pyramid work through the existing workout library. Half-marathon and marathon preparation develop event rhythm; marathon-specific blocks include paced sections in supported long runs, replacing that week's other quality stimulus.
- Marathon long runs can reach 28–32 km when weekly support, recorded long-run capacity, pace-derived duration and actual available visits support them. The 210-minute default is adjustable; it is not a claim that every runner should do 32 km or that an arbitrary duration establishes readiness.
- In a four-run marathon-specific block, a planned long run may use about 45% of weekly distance when separate supporting mileage and the actual visit allow it. This is a scheduling choice, not a universal injury threshold. A completed-marathon athlete with an explicit 240-minute long-run window can receive a conditional longer rehearsal; the output calls for review above 210 minutes and continues to flag missing current long-run history. A slow athlete is not forced into a five-hour 30 km run.
- After an ordered strength-first lead-in, an established runner with completed-marathon evidence can receive a conditional faster aerobic build (6.5% on loading weeks, with consolidation and no added growth in the meet/recovery week). Confirm actual completed work and restored recovery at the handover; future planned kilometres do not establish readiness. The original comparison assumptions yield approximately 55 km/week with a time-bounded 25 km long run for the slower athlete, and approximately 69 km/week with a 31 km long run for the faster athlete after final visit fitting. These are scenario results, not promised performance outcomes.
- Weekly growth depends on the dated priority sequence. A strength-first lead-in is not retroactively treated as running-first training. Consolidation and taper lower volume; recent marathons create provisional easy recovery weeks.
- A later ordered half-marathon or marathon keeps an explicit easy endurance-support base during a strength-first stage. It does not inherit the small general-health mileage cap and does not introduce the later race's hard pace work prematurely. Strength-event and post-meet recovery overrides still apply, and missing long-run history remains a review requirement.
- Structured unresolved lower-body fatigue reduces the running health dose and removes long-run progression. The calendar alone does not clear fatigue. Fitness running after a strength-priority handover is a small easy dose, not a renewed long-running build.
- Unknown race fitness does not prevent general-health running: the engine can prescribe timed conversational runs without fabricating distance or pace. Dated endurance preparation still requires a representative baseline.
- Visit fitting removes ordinary easy padding before reducing warm-up/cool-down to explicit minimums. It retains all quality and recovery intervals or reports a real conflict, recalculates actual distance and duration, and discloses every change. Missing kilometres are never silently added to the long run.
- Known quality visit windows calibrate the work dose before generation; this can shorten each repetition while retaining the planned count and recovery. Work-dose changes are disclosed separately from later easy-distance trimming. Fractional available minutes are rounded down before fitting so a 59.5-minute allowance cannot be exported as a 60-minute run.

The growth rates, phase boundaries, quality shares, duration defaults and review points are explicit product heuristics. They are not universal injury thresholds, validated outcome predictions or substitutes for athlete feedback. The work recognises different demands of marathon-pace practice and faster quality work; the shared engine must recheck intensity against the actual retained calendar.

The module's tests cover supported long-run development and actual pace rehearsals, aspiration isolation, recent-marathon recovery, unknown baselines, ordered-priority progression, unresolved fatigue, exact inclusive visit fitting and timed health-running intake. Current web research lookups returned errors during this implementation; no new paper is claimed as verified evidence for these precise defaults. The pre-existing workout library retains its source notes. Further coaching calibration should review completed athlete work rather than treating synthetic test success as physiological validation.
