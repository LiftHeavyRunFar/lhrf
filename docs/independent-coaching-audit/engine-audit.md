# Engine implementation audit

Audit target: repository commit `0ae327bdb9dfe11e189ff4a9b066d1406bc48f07`, 7 November 2026. Alex traced executable source and reproduced the findings; existing design documents were leads to investigate, not proof of training efficacy. [Characterization tests](../../tests/independent-coaching-audit.test.cjs) call the unchanged canonical engine. [Synthetic replay](../../scripts/independent-coaching-audit.cjs) generates complete blocks without touching app storage, installation, programme replacement, athlete records or production services.

The [evidence review](evidence-review.md) supplies the coaching standard and its confidence/limitations. Numerical engine policies below are not presumed research-derived.

## Entry points and limits of attribution

`coach-adapters.js:21–53` normalizes profile inputs and builds complete weeks. `buildNewProgramme` calls `prepareNewProgramme` before `buildProgramme`; new version-two proposals gain the current markers at `coach-engine.js:132–178`, including `sessionTimeVersion:1`, strength/running evidence and safeguards. A bare `prepareNewProgramme({})` still defaults `coachingRulesVersion:1`; canonical intake explicitly supplies version two at `coach-intake.js:30`. The audit supplies version two, rather than silently testing the older default.

`createEngine` wraps the supplied clock in a local `Date` class (`coach-engine.js:186–190`). This is why generation, dated result checks and replay can be reproduced without changing the host clock. Older `*-v2.js` modules are not the canonical app generator; their passing tests do not validate the current policy.

A complete forward preview and a stored programme are distinct evidence. `index.html:619–620` uses `programme-replacement.js:59` to return a reviewed frozen week when programme IDs match. `reviewedProgramme.weeks`, `activeSchedule`, approved decisions and overrides may therefore differ from a fresh engine run using only `customRoadmap`. `programme-replacement.js:37,71–85` preserves reviewed weeks and protects completed/current dates. `programme-install.js` also contains athlete-specific November refresh branches. None was invoked by this investigation. An observed app session cannot be attributed to a generator branch without its snapshot, policy markers, decisions and provenance.

## Confirmed versus inferred

Recovery scope matters for IA-04: the canonical intake accepts `recoveryContext` independently (`coach-intake.js:40-45`), while the current onboarding UI normally emits both that context and matching `recoveryEvidence` (`index.html:1448-1462`). Matching fatigue evidence does suppress running. The reproduced defect is inconsistent handling of a supported context-only configuration; it is not evidence that every normal onboarding report bypasses running restrictions or that a particular owner device did so.

Confirmed/reproduced defects: approved-duration inconsistency; temporal/record eligibility and 48-hour “multiweek” progression proposal; resolved-marathon lifting override; lower-recovery cross-sport omission. Successful novice straight sets being excluded from positive performance review is a confirmed coverage limitation, with a coaching improvement proposed rather than demonstrated efficacy failure. The register assigns severities and fix scope. Tests deliberately preserve the current defective result so that an eventual correction must update the characterization.

Evidence-supported improvement, without claiming an efficacy failure: expose a minimum effective intended dose and actual removed volume; define success criteria for stable repeated Development work; offer a novice-appropriate review path; reconcile recovery across sports; calibrate taper and mileage convention to observed tolerance; preserve long-term exercise identity when useful; use velocity language honestly. Do not turn any of these into automatic policy changes from this audit.

Unresolved: an athlete's optimal weekly sets, required number of heavy singles, whether speed doubles add value in a particular block, ideal variation schedule, interval family/dose, acceptable taper loss, and how much programme change should follow persistent subjective fatigue without objective decline. The evidence review is the standard for choosing future experiments; the code's thresholds do not settle those questions.
