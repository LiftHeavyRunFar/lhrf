Visual revision
The active exercise now has a firmer electric-blue header band and boundary,
stronger compact angular lettering, tighter corners and greater contrast with
inactive/completed cards. The existing locally licensed Goldman face and heading
size cap are retained. Weight entry has stronger emphasis; numeric targets and
labels have a clearer hierarchy. Redundant active-card summary text is hidden
while the original prescribed weight, sets/reps and target RPE remain visible.
Carry suggestions have one compact contextual line plus a Suggested field label,
not repeated warnings. Completed actuals remain checked values. There are no new
animations, glows, rest controls or workout overlays.

Successful-save gate and progression
The previous draft persist function swallowed storage errors. It now returns an
outcome and verifies the stored JSON by read-back. Set recording takes an in-memory
snapshot before changing completion, suggestions or the next presentation index.
One synchronous write commits the set, draft-only suggestions and resume view.
A write exception or failed read-back restores the prior draft in memory, retains
entered fields, shows an inline retry error and does not move to another exercise.
Validation/equipment failures also leave the current exercise in place.

When a newly recorded set completes the current forward exercise, the existing
card collapses and the next visible incomplete exercise opens in existing order,
with required work preceding optional work as before. Only the small scroll delta
needed to show its controls is applied, instantly; focus is not forced. Detached
button events and rapid repeat actions are guarded. There is no session finish,
submission or completion modal until the athlete explicitly chooses Finish.

Corrections and manual/out-of-order navigation remain under athlete control.
Opening a card records presentation intent synchronously, removing a native-toggle
race during immediate interruption. Draft completion revisions distinguish a
stale tab selection from an intentional current selection. A successful record's
next view is persisted atomically, so an interruption before the DOM transition
still resumes correctly. All-complete state remains pending Finish after reload.

Actual working-load suggestions
The pure training-flow helper carries the latest completed compatible actual load
into untouched later working sets within the same exercise tuple. It supports
increases, decreases and decimal increments. Subsequent actual adjustments replace
only generated/pristine suggestions, never completed actuals or hand-entered values.
Changing a suggested field removes its generated label immediately. Reps and RPE
targets remain unchanged. The common-load prescription stays separate from the
editable values and is displayed from the retained draft prescription snapshot.

A correction to the latest actual can update untouched future suggestions while
staying on that exercise; an older correction cannot override later completed-set
evidence. Manual future values, deliberate blanks, pending corrections and nonempty
untagged legacy fields are protected. No comparison crosses exercise index,
variation, equipment identity, loading unit or dose-unit boundaries. Warm-ups,
prescribed top sets, unknown set roles and explicit per-set/ramping/loading plans
fail closed. A separate later loading phase retains its own prescription.

The existing top-set/RPE back-off FORMULA is unchanged. Its generated back-off
fields are now identified as generated, while existing manual/carry/completed
back-off values are protected. Top-set actual load is never blindly copied as a
back-off load, or into another prescribed top set. Within a compatible uniform
back-off phase, its own actual working load can suggest later working values.
No increased load creates a strength-improvement flag or changes the programme.

Storage and record semantics
All new provenance, original-draft prescription and next-view fields are optional
LIVE-DRAFT metadata. They are created by athlete interaction, not by a migration
or a rewrite of historical data. Existing drafts load without modification. The
finished sets and completed-workout record constructors are unchanged: original
actual weight/reps/RPE/roles and timestamps are recorded as before, with no hint,
manual-edit or navigation metadata added to completed records. No new service,
coaching engine, workout lifecycle, programme activation or database is introduced.

Limitations and review/release boundary
Carry is intentionally conservative for nonempty untagged legacy fields or an
unknown/explicit per-set loading plan. Such values remain available for manual
entry. Automatic progression applies to the normal forward path; manual out-of-
order work and earlier corrections do not force a new card. Original-draft load
is captured before the new transaction changes suggestions; a legacy draft that
already recalculated a back-off before this update cannot reconstruct an unstored
prior draft value. The saved active programme remains unchanged and accessible.
Physical Android keyboard, font scaling/TalkBack and owner visual acceptance
remain necessary. Automated Garmin tests do not establish physical watch delivery.
