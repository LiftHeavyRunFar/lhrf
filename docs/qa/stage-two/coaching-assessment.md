## Genuine shortcomings, ranked

1. **High — explicit event-time allowance is ignored after attendance is confirmed (T).** `coach-constraints.js` accepts `eventDays[date].confirmed === true` without comparing the finite event allowance against estimated race duration and logistics. Even the lower end of 243–250 minutes exceeds 240. The 3:45 aspiration must not be used to make this fit. Proposed correction: enforce the explicit cap separately from permission, return a specific time-conflict/input-review gate and request flexibility or a more appropriate event; retain unlimited strength-event permission when no finite cap was supplied. This is a false event-feasibility result, not a claim that the app guaranteed physiological readiness.
2. **High — maintenance lifting bypasses unresolved fatigue handling (T).** Maintenance is a training objective, not a recovery clearance. The main generator excludes maintenance from `generalStrengthExposureV2`, so its structured fatigue logic never runs. All primary prescriptions are byte-identical when the repeated overshoots and short-sleep context are removed. A diagnostic new proposal using progression mode does invoke the existing recovery response (95 kg squat and 120 kg deadlift controlled triples at RPE 6.5), isolating the branch defect. That probe is not a replacement programme or a recommended mode change. Proposed correction: apply affected-lift recovery logic before progression/maintenance selection, retain normal bench practice, and version any new-proposal policy so existing approved output remains stable.
3. **High — an explicitly longer recovery interval is not enforced within a partial calendar week (S).** Per-session strength recovery stops after seven days, while ordered-goal priority changes only at week boundaries. Nine days after the meet, hard work returns before the ten-day interval completes and before the handover instruction exists. This does not prove injury would occur; it is a reproducible mismatch with the athlete's supplied recovery contract. Proposed correction: evaluate the ordered recovery window on each session's actual date and carry the unresolved recovery review into subsequent preparation; do not infer clearance merely from elapsed days or a Monday boundary.

No engine corrections were made to resolve these findings. The objective audit exits **1 intentionally** while they remain. The frozen contract also defines critical errors; no real-data mutation or unconditional physiological-readiness guarantee was observed here. These high-severity findings are sufficient to withhold coaching sign-off.

## Acceptable differences and conditions, kept separate

- P's one-week taper is a large mileage reduction, but it retains a short current-fitness reminder and the event; it is a defensible 10K taper, not automatically a defect. Monday maintenance before Tuesday quality and Thursday maintenance before Sunday racing warrant individual soreness checks. Two triples at RPE 7.5 for an accustomed lifter are not equivalent to a new maximal strength block.
- Q's Monday squat-first practice can reflect powerlifting event order, even with deadlift priority. Deadlift is given two distinct exposures and a specific final rehearsal. Moving it first is a plausible coach preference, not a demonstrated failure. Four similar initial heavy prescriptions can be effort-led consolidation; static suggested kilograms do not prove a lack of in-session progression from actual performance. Variant loads remain explicitly uncalibrated pending exercise-specific history/warm-ups.
- R's lack of race fitness and a proven whole-visit duration is genuine missing information. Preserve the block. A future time-based/run-walk first-event pathway would improve accessibility, but forcing invented paces or clearing this draft would be the wrong response.
- S's later half-marathon long-run dose and T's marathon preparation remain readiness conditions. Neither an arbitrary minimum longest run nor a passing calendar can certify event readiness. T's persistent easy-only output is an appropriate response to unresolved fatigue; suppressing progression itself is not the bug.
