## Exact changes

- `coach-engine.js`: explicit new version-two proposals receive `coachingSafeguardsVersion: 1`. Saved configs without this marker retain their complete previous output. No app update migrates policies or edits saved schedules/logs.
- `coach-constraints.js`: event permission and time feasibility are separate. `eventDays[date].minutes` remains a hard whole-event window, including logistics. `hardLimitMinutes` is a hard race-duration cutoff, excluding logistics. Both must fit when present. `preferredFinishMinutes` is a soft finish target, and the existing `runningGoalSeconds` remains an aspiration; neither overrides a limit or changes the current-fitness race prescription. Unknown duration cannot establish that a finite window fits. Unlimited confirmed strength events retain an unknown duration; a finite strength-event window needs `estimatedMinutes`. Conflicts mark the event and week infeasible and explain the options: confirm genuine additional availability, select a suitable event/date or defer participation, rather than prescribing faster pace to hide the conflict.
- `coach-intake.js`: preserves and validates the distinct cutoff, preference and explicit-duration fields. The canonical proposal boundary also rejects invalid event values. No view implements replacement feasibility logic.
- `coach-engine.js`: affected maintenance squat/deadlift use the existing effort-led recovery response and observed load anchor. Normal bench is preserved. Low-value support is omitted while movement practice remains. Already-light taper/recovery doses are retained rather than increased; deload volume does not increase. Novice/returning maintenance retains a conservative easy triple. Explicit current lower/all-body recovery reports are usable even without a manufactured designated-top-set history; future reports are excluded. Sleep and long-run recovery remain observations, not fabricated readiness scores. Explicit clearance is distinct from elapsed weeks.
- `coach-engine.js`: ordered recovery intervals are checked using each session's UTC date. The stated interval is active while `0 < daysAfterEvent < recoveryDays`; thus Idris's day nine is still protected, including a partial training week. Strength is light/resting, supporting volume is reduced, and any long/quality run within the interval becomes short easy recovery work. The review instruction exists before the next Monday priority handover and remains a condition for subsequent hard work. A calendar interval ending does not establish physiological recovery.
- `tests/stage-three-safeguards.test.cjs`: 12 new tests cover hard versus soft event times, logistics/cutoff boundaries, unknown/unlimited events, intake validation, all five frozen athletes, conservative maintenance recovery, arbitrary 10/14/21-day intervals, UK DST, saved programmes/logs and browser-global parity. The existing intake browser test is strengthened to reject a confirmed but insufficient 130-minute event window before accepting 150 minutes. Existing criteria were not loosened.
